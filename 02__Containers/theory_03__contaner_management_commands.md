### Команды управления контейнером

| Команда          | Обязательное  | Опциональное                   | Краткое описание                                  |
| ---------------- | ------------- | ------------------------------ | ------------------------------------------------- |
| `docker create`  | `<IMAGE>`     | `[OPTIONS]`                    | Создаёт контейнер из образа, но не запускает его  |
| `docker run`     | `<IMAGE>`     | `[OPTIONS] [COMMAND] [ARG...]` | Создаёт новый контейнер из образа и запускает его |
| `docker start`   | `<CONTAINER>` | `[OPTIONS]`                    | Запускает существующий контейнер                  |
| `docker stop`    | `<CONTAINER>` | `[OPTIONS]`                    | Корректно останавливает работающий контейнер      |
| `docker pause`   | `<CONTAINER>` | —                              | Приостанавливает процессы внутри контейнера       |
| `docker unpause` | `<CONTAINER>` | —                              | Возобновляет выполнение процессов в контейнере    |
| `docker restart` | `<CONTAINER>` | `[OPTIONS]`                    | Перезапускает существующий контейнер              |
| `docker kill`    | `<CONTAINER>` | `[OPTIONS]`                    | Принудительно завершает работающий контейнер      |
| `docker rm`      | `<CONTAINER>` | `[OPTIONS]`                    | Удаляет существующий контейнер                    |

**Обозначения:**

* `<IMAGE>` — имя или ID Docker-образа
* `<CONTAINER>` — имя или ID Docker-контейнера
* `[OPTIONS]` — необязательные параметры команды
* `[COMMAND]` — необязательная команда, выполняемая в контейнере
* `[ARG...]` — необязательные аргументы команды

---

#### Удаляем все остановленные контейнеры

```bash
docker rm $(docker ps -aq)
```
или

```bash
docker container prune
```

---

#### `docker kill` vs `docker stop`

| Команда       | Что делает                            |
| ------------- | ------------------------------------- |
| `docker stop` | Штатно останавливает контейнер        |
| `docker kill` | Принудительно останавливает контейнер |

```text
RUNNING
   │
   ├── docker stop ──► STOPPED
   │
   └── docker kill ──► STOPPED
```

* `stop` → сначала отправляет `SIGTERM`, давая процессу возможность корректно завершиться.
* `kill` → по умолчанию отправляет `SIGKILL`, немедленно завершая процесс.

Обе команды **не удаляют контейнер**.
