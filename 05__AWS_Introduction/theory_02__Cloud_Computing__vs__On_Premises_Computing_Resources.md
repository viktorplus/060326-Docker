### Облачные вычисления vs Собственные вычислительные ресурсы (On-Premise)


| Критерий                                 | Облако                                                            | On-premise                                           |
|------------------------------------------|-------------------------------------------------------------------|------------------------------------------------------|
| **Модель затрат**                        | OPEX (операционные расходы, "плати по мере использования")        | CAPEX (крупные первоначальные капитальные вложения)  |
| **Скорость запуска**                     | Минуты–часы (ресурс уже готов)                                    | Недели–месяцы (закупка, доставка, монтаж, настройка) |
| **Масштабируемость**                     | Эластичная — вверх и вниз почти мгновенно                         | Ограничена физически купленным оборудованием         |
| **Обслуживание/поддержка**               | На стороне провайдера (патчи, железо, охлаждение, электричество)  | Полностью на компании — свой штат админов            |
| **Контроль над данными**                 | Ограничен политиками провайдера, зависит от юрисдикции ЦОД        | Полный физический и юридический контроль             |
| **Безопасность**                         | Отвечает провайдер (по модели shared responsibility) + сам клиент | Полностью на компании — и плюс, и минус              |
| **Отказоустойчивость**                   | Встроенная (обычно 99.9%+)                                        | Нужно строить самостоятельно — дорого                |
| **Предсказуемость расходов**             | Может "плавать" при непредсказуемой нагрузке                      | Стабильна после первоначальных вложений              |
| **Зависимость от интернета**             | Критична — без сети нет доступа к ресурсам                        | Не требуется (для внутренних систем)                 |
| **Vendor lock-in**                       | Высокий риск привязки к экосистеме провайдера                     | Отсутствует                                          |
| **Соответствие регуляторике**            | Может быть сложнее (данные "где-то в облаке")                     | Проще для строгих требований (гостайна, спецданные)  |
| **Экономика в долгосрочной перспективе** | Дороже при стабильной высокой нагрузке 24/7                       | Дешевле при стабильной предсказуемой нагрузке        |

---

## Когда выгоднее облако

- Нагрузка непредсказуема или сезонна (пики продаж, стартапы, растущий бизнес)
- Нет своей инфраструктуры и штата специалистов
- Нужен быстрый выход на рынок (time-to-market)
- Проекты с коротким жизненным циклом (пилоты, MVP)
- Географически распределённая аудитория (нужны дата-центры по всему миру)

## Когда выгоднее свои ресурсы

- Стабильная предсказуемая нагрузка на протяжении многих лет
- Жёсткие требования регуляторов (гостайна, банковская тайна, персональные данные с обязательной локализацией)
- Уже есть built-in инфраструктура и штат специалистов
- Специфическое "железо"
- Критично полный контроль над физическим доступом к данным
