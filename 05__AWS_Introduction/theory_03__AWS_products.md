### Amazon EC2 (`Elastic Compute Cloud`) — сервис `IaaS`

**"Голое железо" в аренду**.  
Максимум гибкости и контроля, минимум готовых абстракций.

**Провайдер**: 
- предоставляет виртуальные серверы (вычислительные мощности) по требованию,
- и отвечает за их доступность и исправность

**Пользователь**
- сам выбирает конфигурацию, 
- устанавливает ОС, 
- разворачивает и настраивает любое ПО, 
- полностью управляет виртуальной машиной. 

**Область применения**:
- хостинг веб-приложений, требующих полного контроля над серверным окружением.

**Конкуренты**:
- GCP: Google Compute Engine (GCE)
- Azure: Azure Virtual Machines (VMs)

### Amazon S3 (`Simple Storage Service`) — сервис `STaaS` (подвид `PaaS`)

**Безлимитное облачное хранилище объектов**.  
Максимум надёжности и доступности, минимум забот об инфраструктуре хранения.

**Провайдер**:
- предоставляет распределённое хранилище для файлов (объектов) любого типа и объёма,
- обеспечивает избыточность, репликацию, доступность и защиту данных

**Пользователь**:
- загружает и скачивает файлы через API/консоль,
- организует данные в «бакеты» (buckets),
- настраивает права доступа, версионирование, политики жизненного цикла,
- не управляет ни серверами, ни файловой системой напрямую.

**Область применения**:
- хранение статики (изображения, видео, бэкапы), 
- архивация данных, 
- хостинг статических сайтов, 
- промежуточное хранилище для аналитики и ML.

**Конкуренты**:
- GCP: Google Cloud Storage (GCS)
- Azure: Azure Blob Storage

### Amazon RDS (`Relational Database Service`) — сервис `DBaaS` (подвид `PaaS`)

**Сервис для управления реляционными базами данных**.  
Максимум удобства администрирования, минимум забот об инфраструктуре СУБД.

**Провайдер**:
- разворачивает и поддерживает реляционную СУБД (MySQL, PostgreSQL, MariaDB, Oracle, SQL Server),
- берёт на себя резервное копирование, репликацию, патчи, масштабирование, отказоустойчивость

**Пользователь**:
- создаёт схему БД, пишет запросы, работает с данными через стандартный SQL-интерфейс,
- настраивает параметры экземпляра (размер, регион, репликация),
- не управляет ни сервером, ни установкой/обновлением самой СУБД.

**Область применения**:
- бэкенды приложений с чёткой структурой данных и потребностью в транзакциях 
  - интернет-магазины, 
  - финансовые системы, 
  - ERP.

**Конкуренты**:
- GCP: Cloud SQL
- Azure: Azure SQL Database

### Amazon DynamoDB — сервис `DBaaS` (подвид `PaaS`)

**Управляемая NoSQL-база данных «под ключ»**.  
Максимум скорости и масштабируемости, минимум настройки схемы.

**Провайдер**:
- предоставляет полностью управляемую key-value/документную БД,
- обеспечивает автоматическое масштабирование, репликацию, отказоустойчивость без вмешательства пользователя

**Пользователь**:
- определяет таблицы и ключи (без строгой фиксированной схемы),
- работает с данными через API (без SQL),
- настраивает пропускную способность (или использует on-demand режим),
- не управляет ни серверами, ни внутренней архитектурой хранения.

**Область применения**:
- приложения с высокой нагрузкой и требованием низкой задержки 
  - игры, 
  - IoT, 
  - мобильные бэкенды, 
  - real-time сервисы

**Конкуренты**:
- GCP: Firestore / Cloud Bigtable
- Azure: Cosmos DB

### AWS Lambda — сервис `FaaS` (serverless, подвид `PaaS`)

**Код без сервера**.  
Максимум абстракции от инфраструктуры, минимум забот о запуске и масштабировании.  
> Сервер физически существует — просто им управляет AWS, а не Клиент).  
> Когда приходит событие-триггер, AWS:
> - поднимает изолированный контейнер (микро-ВМ),
> - разворачивает туда пакет Клиента (код + зависимости),
> - выполняет функцию,
> - после простоя — уничтожает контейнер 
>   - (либо оставляет "тёплым" на время для повторных вызовов).

**Провайдер**:
- предоставляет среду выполнения для отдельных функций (кода) по событию/запросу,
- автоматически выделяет ресурсы, масштабирует (в том числе до нуля), обеспечивает отказоустойчивость

**Пользователь**:
- пишет только код функции (на Python, Node.js, Java и др.),
- настраивает триггеры (события, вызывающие функцию: HTTP-запрос, изменение в S3, сообщение в очереди и т.д.),
- не управляет ни серверами, ни средой выполнения, ни масштабированием,
- платит только за количество вызовов и время выполнения функции.

**Область применения**:
- обработка событий, 
- микросервисы, 
- бэкенды без постоянной нагрузки (обработка файлов, API-эндпоинты с нерегулярным трафиком).

**Конкуренты**:
- GCP: Cloud Functions
- Azure: Azure Functions

### Amazon VPC (`Virtual Private Cloud`) — сервис `IaaS` (сетевой сегмент, иногда выделяют как `NaaS`)

**Изолированная виртуальная сеть в облаке**.  
Максимум контроля над сетевой топологией, минимум забот о физическом сетевом оборудовании.  
**Важно**:
- Если в этой сети участвуют сервисы AWS, то им не обязательно публичный ip-адрес
  - (в AWS за публичный ip сервиса — отдельная плата, которую здесь можно избежать!)

**Провайдер**:
- предоставляет физическую сетевую инфраструктуру (коммутаторы, маршрутизаторы, каналы связи),
- обеспечивает изоляцию сети клиента от других арендаторов, отказоустойчивость сетевого уровня

**Пользователь**:
- сам проектирует топологию сети: создаёт подсети (subnets), задаёт диапазоны IP-адресов,
- настраивает 
  - таблицы маршрутизации, 
  - шлюзы (Internet Gateway, NAT Gateway), 
  - правила безопасности (Security Groups, NACL),
- полностью управляет логической структурой сети 
  - (аналогично тому, как в EC2 управляют виртуальной машиной, только здесь — сетью).
- (выглядит сложно, но в любом случае, это **намного проще, чем создать собственную сеть "с нуля"**)

**Область применения**:
- изоляция ресурсов по средам (dev/stage/prod), 
- построение гибридных сетей (VPN/Direct Connect с локальной инфраструктурой), 
- сегментация по требованиям безопасности (например, отдельная подсеть для БД без прямого доступа из интернета).

**Конкуренты**:
- GCP: Virtual Private Cloud (VPC)
- Azure: Virtual Network (VNet)

### Amazon Route 53 — сервис `PaaS` (DNS-сервис, специализированный сетевой сервис)

> Как и с S3 — сервис узкоспециализированный (только DNS), поэтому логичнее относить его к подвиду **PaaS**, а не выделять как отдельную инфраструктурную категорию наравне с VPC/EC2.

**Управляемый DNS в облаке**.  
Максимум надёжности разрешения имён, минимум забот об администрировании DNS-серверов.  
**Важно**:
- Как и в предыдущим случае, можно сэкономить на публичных ip-адресах AWS сервисов.

**Провайдер**:
- предоставляет глобально распределённую DNS-инфраструктуру (сеть DNS-серверов по всему миру),
- обеспечивает высокую доступность, отказоустойчивость и низкую задержку при разрешении имён

**Пользователь**:
- регистрирует и/или подключает домены,
- создаёт записи DNS (A, CNAME, MX, TXT и др.),
- настраивает политики маршрутизации трафика (по задержке, geolocation, weighted, failover),
- не управляет ни серверами, ни программным обеспечением DNS напрямую.

**Область применения**:
- управление доменными именами, 
- балансировка нагрузки на уровне DNS, 
- отказоустойчивая маршрутизация трафика между регионами, 
- проверка работоспособности (health checks) конечных точек.

**Конкуренты**:
- GCP: Cloud DNS
- Azure: Azure DNS


Возможны 2 варианта `Hosted Zone`:

#### 1. Public Hosted Zone — "доменное имя для всех"

- Видна **всему интернету** — любой человек в мире, кто наберёт имя домен, получит ответ от Route 53.
- Это фактически означает, что Route 53 **выступает официальным authoritative DNS-сервером** для этого домена
  - (по сути, это замена/альтернатива «обычному» DNS-провайдеру).
- Чтобы это заработало, необходимо **прописать NS-серверы Route 53 у регистратора домена** 

#### 2. Private Hosted Zone — "доменное имя только для своих"

- Видна **только внутри указанного VPC** (одного или нескольких).
- Снаружи этой сети (из обычного интернета) такие домены **не резолвятся вообще** — их не существует для внешнего мира.
- Используется для внутренних имён компании: 
  - (чтобы серверы внутри VPC могли обращаться друг к другу по-человечески читаемым именам, а не по IP)


|                         | Public Hosted Zone           | Private Hosted Zone                                   |
|-------------------------|------------------------------|-------------------------------------------------------|
| Кто видит               | Весь интернет                | Только ресурсы внутри конкретного VPC                 |
| Заменяет ли внешний DNS | Да, полностью                | Нет — работает только «внутри двора»                  |
| Пример                  | `mysite.com` — сайт компании | `db.internal` — внутренний адрес БД для микросервисов |

### Amazon VPC vs Route 53

| Критерий                   | Amazon VPC                                                                                       | Amazon Route 53                                              |
|----------------------------|--------------------------------------------------------------------------------------------------|--------------------------------------------------------------|
| **Тип сервиса**            | IaaS (сетевая инфраструктура)                                                                    | PaaS-подвид (управляемый DNS)                                |
| **Что предоставляет**      | Изолированную виртуальную сеть (подсети, IP-адресация, маршрутизация)                            | Разрешение доменных имён в IP-адреса                         |
| **Основная задача**        | Как ресурсы взаимодействуют друг с другом и с интернетом                                         | Как пользователи/клиенты находят наши ресурсы по имени       |
| **С чем работает**         | Внутренняя топология сети (приватная/публичная)                                                  | Внешние доменные имена (публичные, реже приватные DNS)       |
| **Аналогия**               | Строим здание и его внутренние коридоры/двери                                                    | Вешаем табличку с адресом, чтобы люди могли найти здание     |
| **Без него**               | Ресурсы вообще не смогут взаимодействовать в сети                                                | Ресурсы доступны только по IP, без человекочитаемых имён     |
| **Пример использования**   | Разделить сеть компании на "для сотрудников" и "для серверов" (закрыть серверы от "кого угодно") | По имения `example.com` открывать наш сайт, а не чей-то иной |

#### Суть разницы одной фразой

* **VPC** — это **где** живут наши ресурсы и **как** они соединены между собой.
* **Route 53** — это **как их найти по имени** снаружи (или внутри) этой сети.
