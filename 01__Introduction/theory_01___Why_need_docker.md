## Зачем нужен Docker?

### Проблема
* Обычная установка программ **индивидуальна** для каждой рабочей среды.
* Причина:
  * **разные ОС** (и по типу, и по версиям)
  * на которые предварительно уже установлены **разные программы**
* Поэтому установить **одну** программу на несколько **разных** устройств — "отдельный вид искусства"


### Идея
Устанавливать программу на 
  * "пустые"
  * и одинаковые

машины.

Тогда на каждую из них можно установить абсолютно одинаковое программное окружение.

А сама установка и запуск конечной программы перестанет быть "лотереей".

## Решение 1: Виртуализация

**Виртуализация** — это технология создания виртуальной версии 
* компьютера, 
* операционной системы, 
* сети 
* или другого ресурса  

с помощью **гипервизора**.

**Гипервизор (hypervisor)** — это специальное программное обеспечение, которое 
* создаёт виртуальные машины
* и управляет ими.

Иными словами,

    Гипервизор — это "посредник" между физическим и виртуальными компьютерами.

```
Физический компьютер
│
├── CPU
├── RAM
├── Диск
└── Сеть
       │
       ▼
   ГИПЕРВИЗОР
       │
       ├── Виртуальная машина №1
       │      ├── виртуальный CPU
       │      ├── виртуальная RAM
       │      ├── виртуальный диск
       │      └── Ubuntu
       │
       ├── Виртуальная машина №2
       │      ├── виртуальный CPU
       │      ├── виртуальная RAM
       │      ├── виртуальный диск
       │      └── Debian
       │
       └── Виртуальная машина №3
              ├── виртуальный CPU
              ├── виртуальная RAM
              ├── виртуальный диск
              └── Windows
```

---


### Что конкретно делает гипервизор?

1. **Создаёт виртуальные машины**.
2. **Выделяет им ресурсы** физического компьютера.
3. **Изолирует виртуальные машины** друг от друга.
4. Предоставляет им **виртуальное оборудование**:

   * CPU
   * RAM
   * диск
   * сетевую карту и т. д.
5. Управляет доступом нескольких VM к одному физическому оборудованию.


---


### Два основных типа гипервизоров

#### Type 1. Гипервизор непосредственно на железе

```text
    Hardware
       ↓
   Гипервизор
       ↓
 ┌─────┼─────┐
 ↓     ↓     ↓
 VM    VM    VM
 ↓     ↓     ↓
 ОС    ОС    ОС
```

Type 1 — гипервизор является основным программным слоем над железом.

Обычно используется на серверах и в дата-центрах.

Примеры:

* VMware **ESXi**
* Microsoft **Hyper-V** (в серверном сценарии)

---

#### Type 2. Гипервизор поверх основной ОС

```text
    Hardware
       ↓
   Основная ОС
       ↓
   Гипервизор
       ↓
 ┌─────┼─────┐
 ↓     ↓     ↓
 VM    VM    VM
 ↓     ↓     ↓
 ОС    ОС    ОС
```

Type 2 — гипервизор работает как обычное приложение внутри основной ОС.  

Это проще и удобнее для пользователя, но добавляет дополнительный слой OC и накладные расходы.

Примеры:

* **VirtualBox**


---

**Плюс**: 
* На базе одной реальной машины получаем несколько виртуальных

**Минус:** 
* Сложность создания и настройки каждой виртуальной машины
* Каждая виртуальная — почти полный аналог реальной, следовательно 
  * содержит в себе много лишнего
  * что увеличивает накладные расходы

## Решение 2: Контейнеризация (Docker)

Виртуализация решает проблему через создание **целой виртуальной машины**.

Docker решает задачу проще:

* вместо затратного клонирования виртуальных машин с собственной ОС;
* использует **одно** общее Linux-ядро **для всех** контейнеров;
* упаковывает программу вместе с тем, что ей необходимо для работы;
* запускает эту упаковку в отдельном **контейнере**.


    Примечание:
    На Mac и Windows Docker работает внутри виртуальной Linux-машины

### Что такое контейнер?

**Контейнер** — это изолированная среда, в которой программа
запускается вместе со своими зависимостями.

Условно:

```text
        Физический компьютер
        │
        ├── ОС
        │
        └── Docker
              │
              ├── Контейнер №1
              │      └── Программа + зависимости
              │
              ├── Контейнер №2
              │      └── Программа + зависимости
              │
              └── Контейнер №3
                     └── Программа + зависимости
```

---

### VM vs Docker Container

|                             | **Виртуальная машина (VM)**            | **Контейнер (Docker)**                         |
|-----------------------------|----------------------------------------|------------------------------------------------|
| Что создаём?                | Виртуальный компьютер                  | Изолированную среду для программы              |
| Что изолируем?              | Весь компьютер                         | Программу и её окружение                       |
| Ядро ОС                     | Собственное для каждой VM              | Одно общее Linux-ядро на всех                  |
| Ресурсы                     | Обычно резервируются при создании      | "Ест из общей кучи", пока его не ограничили    |
| Перераспределение ресурсов? | Ограниченное (зависит от гипервизора)  | Гибкое (особенно CPU и память)                 |
| Запуск                      | Относительно медленный                 | Быстрый                                        |
| Размер                      | Большой                                | Обычно значительно меньше                      |
| Основное применение         | Запуск разных ОС, сильная изоляция     | Упаковка, перенос и масштабирование приложения |
| Аналогия                    | Ещё один (почти) полноценный компьютер | Отдельная коробка для программы                |
