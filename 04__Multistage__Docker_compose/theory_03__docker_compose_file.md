## Модель приложения Compose

`docker-compose.yml` представляет собой спецификацию приложения Compose.

Спецификация описывает приложение тремя основными абстракциями (плюс configs/secrets).

### 1. Services (сервисы)

Сервис — это не контейнер, а "рецепт контейнера" (или группы одинаковых контейнеров): 
* образ или сборка, 
* команда, 
* порты, 
* env, 
* тома, 
* лимиты, 
* зависимости 
* и прочее

Имя сервиса важно: 
* внутри сети проекта другие сервисы обращаются к нему **по имени сервиса как по hostname** 
  * (Своего рода "местная DNS Compose")


### 2. Networks (сети)

Сеть — канал связи между сервисами.  

Если сети не объявлены в Compose-файле, то 
* Compose создаёт **сеть по умолчанию** (обычно `bridge`) 
* и подключает к ней все сервисы. 


### 3. Volumes (тома)

Том — постоянное хранилище, живущее дольше контейнера.   
Без тома данные БД исчезнут при `down`/`rm`.

Два основных способа монтирования данных:

- **именованные тома** (`db_data:`) — ими управляет Docker;
- **bind mounts** (`./src:/app`) — каталог с хоста, удобно в разработке.

### Дополнительно: configs и secrets

Конфиги — несекретные файлы конфигурации, монтируемые в контейнер.  
Secrets — чувствительные данные (пароли, ключи) с более осторожной моделью передачи.  
На чистом Docker Engine поддержка слабее, чем в Swarm/K8s, но в спецификации они есть.
