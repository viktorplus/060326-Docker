### Multi-stage build

В прошлый раз для облегчения образа мы удалили [кэш пакетного менеджера](../03__Dockerfile__Volume/theory_04__Image_size_optimization.md)

Это позволило сократить объём почти вдвое.

Тем не менее команда `rm -rf /var/lib/apt/lists/*`удаляет только кэш пакетного менеджера,  
но не сами установленные программы, которые весят существенно больше.

С помощью `Multi-stage build` (сборки образа в несколько этапов):
- мы устанавливаем инструменты, необходимые для сборки в промежуточный образ;
- создаём с помощью этих инструментов необходимые нам зависимости;
- а затем копируем **только** то, что нужно в образе.
- при этом промежуточные слои могут оставаться в `Docker build cache`
  - (который, как мы уже знаем, полезно регулярно чистить).


#### Пример

```dockerfile
RUN apt-get update && apt-get install -y build-essential
```

В этом примере пакет `build-essential` содержит компиляторы и инструменты сборки:

```text
build-essential
 ├── gcc
 ├── g++
 ├── make
 └── ...
```

Сами по себе они не нужны, нужен только результат их работы.

Multi-stage делает именно это: он вообще не переносит эти пакеты в финальный образ:

```text
builder:
    build-essential ──┐
    gcc               │
    make              │
                      X  не попадают
final:                │
    приложение  ←─────┘
```

Поэтому:

* очистка apt-кэша → убирает временные файлы;
* multi-stage → позволяет вообще не иметь в финальном образе инструменты сборки.

Именно поэтому multi-stage может дать гораздо больший выигрыш.




#### `Multi-stage build` — это сборка Docker-образа в несколько этапов.

Каждый этап начинается с `FROM`:

```dockerfile
FROM python:3.9-slim AS builder
# сборка приложения

FROM python:3.9-slim
# финальный образ
```

Главная идея:

```text
builder → собираем приложение
              ↓
         COPY --from=builder
              ↓
final   → только то, что нужно для запуска
```

Первый этап может содержать компиляторы, `build-essential` и другие инструменты сборки.

В финальный этап они не попадают, если их явно не скопировать.

Поэтому финальный образ получается значительно меньше.

```Dockerfile
# Финальный этап
FROM python:3.9-slim
WORKDIR /app

# Копирование файлов из стадии сборки
COPY --from=builder /app /app
COPY --from=builder /root/.local /root/.local

```

Первый этап после сборки не становится частью финального образа.    
Но его данные могут оставаться в `Docker build cache`.
